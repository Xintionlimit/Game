# v0.4.0 质量整改与持续试玩记录

## 整改范围

1. 去除厨房背景内重复的碗与砧板，扩大真实操作台面；重排独立厨具图集，消除裁切混入的碎片。
2. 人物对齐前台柜沿，加入前景出餐台和接触阴影；厨具位置与操作区一致。
   末次画面检查同时替换尸变顾客的半身立绘，使用同一人物对应的全身感染者资源，避免防线出现漂浮头像。
3. 加入刀具、菜片、切割火花、焊接光、炮塔后坐、敌人命中/倒地和原创合成声音；音效需用户首次操作解锁，可关闭。
4. 加入五场景夜间图、星空、窗灯与统一昼夜渐变；非相邻滑动回弹，不再任意拖进空白角落。
5. 建塔后继续提供接待伙伴、后续信标、三路布防、自动切菜/灌溉、维修工具、求救等目标；生产选择仍由玩家决定。
6. 补齐白天来客、夜间停止接客、日配额、延迟来客、失败访客进入防线、不掉材料、弹匣换弹、独立炮塔耐久与六秒维修。
7. v1存档迁移到v2，保留资源、塔位和信标检查点；主档损坏尝试有效备份；存储受限时显示提示。

## 正式构建持续触摸试玩

- 墙钟时长：1332.503 秒，约 22 分 12 秒。
- 环境：Chromium，390×844，实际 CDP 触摸事件，生产预览构建。
- 起点：全新浏览器上下文、全新存档。
- 观察接口只能返回状态副本；测试脚本没有写资源、改进度、调时钟或设置伤害。
- 完成：31份料理、29次出餐、15次加工、三路炮塔、二阶和三阶信标、自动灌溉、自动切菜，达到第8个游戏日，击杀140个敌人。
- 覆盖：白天、夜晚、第7夜血月、手动暂停与恢复、浏览器刷新后恢复。
- 结果：无脚本异常、无教学回退、无失守、无无效或负库存；记录中有5位未及时接待的客人，属于失败分支而非测试通过的出餐。
- 这轮防守中没有发生炮塔受损，因此长测的维修次数为0；维修由下面的独立受损存档场景验证，不能宣称长测自然覆盖了维修。

原始证据：`v0.4.0-evidence/long-play-result.json` 和 `long-play-progress.json`。可复现脚本：`scripts/qa-long-play.mjs`。

## 发现后的修正与最终回归

- 长测复核发现血月按午夜截断。最终规则改为“夜晚归属于开始的那个游戏日”，第7夜跨午夜保留，到第8日清晨结束；添加边界回归并重新构建/执行浏览器检查。
- 明确区分长测所加载的中间构建与最终边界修复：最终改动由跨午夜规则测试和浏览器专项验证，未再声称对最终每个字节重复22分钟长测。
- 最终规则测试包含23项；完整浏览器场景包含7项，覆盖四屏尺寸、从零触摸新手链、厨房、出餐造塔、维修、后续选择/取消返料与自动切菜。
- 维修专项从受损存档起点，通过点击受损炮塔消耗一份工具；重复点击不再扣费，切场景后六秒恢复，等级与塔位保留。

## 验收边界

本轮验证的是可以持续经营的基础游戏版本与质量修复，不等于216项全部最终内容已完成。实体iPhone/Android、更多菜谱作物、完整逐帧角色动画和正式终章围攻演出仍需后续验收。所有“实际操作”在本报告中特指浏览器触摸模拟，不冒充实体手机人工试玩。
